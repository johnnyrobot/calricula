# Task 5 Report: Chat persistence (conversations, messages, runs, events) and migration

## What I implemented

`backend/app/chat/models.py` — four SQLModel table models, following the
conventions in `identity/models.py` / `collaboration/models.py` (UUID PKs
with `default_factory=uuid.uuid4`, `created_at` via `datetime.now(timezone.utc)`,
plural snake-case `__tablename__`):

- `Conversation` — `org_id`/`workspace_id`/`user_id` nullable FKs,
  `principal_kind: str` ("user"|"public"), `context_id: str`,
  `scope: dict` (`sa_column=Column(JSON)`), `language: str`, `expires_at`.
- `Message` — `conversation_id` FK, `role: str` ("user"|"assistant"),
  `content: str`, `answer: dict | None` (JSON).
- `ChatRun` — `conversation_id` FK, `message_id` FK, `context_id: str`,
  `status: str` ("queued"|"running"|"completed"|"failed"|"cancelled"),
  `started_at`/`finished_at`/`error_code`.
- `RunEvent` — `run_id` FK, `seq: int`, `type: str`, `payload: dict` (JSON),
  with `__table_args__ = (UniqueConstraint("run_id", "seq", name="uq_run_events_run_id_seq"),)`.

All `str`-typed enum-like fields (`principal_kind`, `role`, `status`) are
plain columns with the allowed values documented in each model's docstring,
per the brief's "keep it simple" instruction — no Postgres enum types.

### `model_post_init` choice

Used `model_post_init(self, __context)` on `Conversation`, as the brief's
primary suggestion. I verified directly (via `test_public_conversation_gets_expiry`)
that SQLModel's table metaclass does *not* skip it: `Conversation(principal_kind="public", ...)`
correctly gets `expires_at` set before `session.add()`/`commit()`. No need to
fall back to `@model_validator(mode="after")`. Environment: `sqlmodel==0.0.14`,
`pydantic==2.13.4`.
