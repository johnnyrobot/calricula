## How the test DB is created

Per the controller's ruling, `backend/tests/conftest.py` does **not** assume `applicationx_test` already exists. Before the session-scoped `engine` fixture builds the SQLAlchemy engine, `_ensure_test_database_exists()`:
1. Parses `settings.DATABASE_URL` (already pointed at `applicationx_test` — see below) with `urllib.parse`.
2. Connects with `psycopg2` to the `postgres` maintenance database on the same host/port/credentials.
3. Sets `autocommit = True`, checks `pg_database` for the target db name, and issues `CREATE DATABASE "applicationx_test"` if it's missing.

This runs lazily inside the `engine` fixture (session-scoped), so P0 tests that never request `session`/`client` don't touch Postgres at all — matching the "must keep the DB-creation and engine fixtures lazy" requirement.

**One deviation from the brief's literal conftest snippet, made to satisfy the harder constraint ("existing test suite must keep passing"):** the brief's `os.environ.setdefault("DATABASE_URL", ...)` call, run unconditionally at conftest import time, permanently pollutes `os.environ` for the whole pytest session. `tests/test_config.py::test_defaults_are_local_and_safe` calls `Settings(_env_file=None)`, which (via pydantic-settings) still reads live process env vars regardless of `_env_file`, and asserts `DATABASE_URL` ends with `:5434/applicationx` (the *dev* URL) — so a leaked `DATABASE_URL=...applicationx_test` env var broke that pre-existing P0 test. Fix: conftest now records whether `DATABASE_URL` was already present in `os.environ` before the `setdefault` call, uses `setdefault` to steer the one-time construction of the `app.core.config.settings` singleton (which is what `database.py`, `alembic/env.py`, and the fixtures actually consume), and then — if the key wasn't present beforehand — deletes it from `os.environ` immediately after the `settings`/`database`/`models_registry` imports. The `settings` singleton keeps its already-resolved `applicationx_test` URL (Python module caching), so the fixtures are unaffected; `os.environ` is clean again for every other test in the session, including `test_config.py`. Rest of conftest (session-scoped `engine` with `drop_all`/`create_all`, per-test `session` with `TRUNCATE ... CASCADE`, `client` overriding `get_session`) matches the brief verbatim.
